# Mock claims

Generated by `scripts/make_mockclaims.py`; edit that script, not these files.
Each folder is one adversarial case: `description.txt`, the submitted documents, `claim.json`
(policy, submission date, what the case tests), `oracle.json` (what the model would have answered)
and `expected.json` (the required decision and payout).

`01`-`18` and `g01`-`g04` test one rule each, with tidy documents. The `b` claims are shaped like
the real claims and target what the first blind run got wrong: no stated cover period, names
written differently on each document, certificates as WebP photos or as JPEGs named `.webp`, a
certificate for someone else, one altered digit, a letter dated late with no submission date,
an unstated prior condition, a missed departure that is not a cancellation, a submission date
found only in the intake system's `Current date is` stamp, a booking that says it was already
refunded (the reader must flag what no rule looks for). Most come in pairs
that differ in one detail, so the strategies can be compared claim by claim.
